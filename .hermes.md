# Hermes instructions for drquarrier-site

This repository is the source for `https://drquarrier.com`.

## Repository workflow

- Forgejo `origin` is the source of truth.
- GitHub is a downstream mirror; never push to GitHub directly.
- Begin each task from an updated `origin/main`.
- Create a branch named `hermes/<short-task-name>` for every change.
- Never push directly to `main` and never force-push.
- Commit only files relevant to the requested task.
- Push the Hermes branch to Forgejo and report the branch name, commit, tests, and a concise change summary for pull-request review.

Suggested start:

```bash
git switch main
git pull --ff-only origin main
git switch -c hermes/<short-task-name>
```

## Validation

- Run `npm ci` when dependencies or the lockfile may have changed.
- Run `npm run build` before proposing any website change.
- Treat build warnings and failures as blockers; do not hide or bypass them.
- Review `git diff` and `git status --short` before committing.

## Deployment boundary

- A Git push does not deploy the website.
- Do not run `wrangler deploy`, alter Cloudflare, purge caches, or change DNS unless Scott explicitly requests a production deployment.
- Follow `DEPLOY.md` for the current operator-run deployment process.

## Safety and privacy

- Never commit API tokens, SSH private keys, Wrangler credentials, `.env` files, passwords, session logs, private Hermes memory, research working files, or protected health information.
- Do not weaken `robots.txt`, security headers, branch protection, or repository visibility without explicit approval.
- Keep patient-facing medical language accurate, appropriately qualified, and consistent with the cited evidence already in the project.
